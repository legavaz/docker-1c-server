# Веб-страницы и адреса проекта

Адреса для локальной сети. Хост VM `kali` — `192.168.1.51`. Токен команды (`BSL_SERVICE_TOKEN`) хранится в `DEPLOY.local.md`, в документацию его не переносим.

## Сервис проверки BSL (`bsl-api`, порт 8080)

| Страница | Адрес | Токен | Назначение |
|---|---|---|---|
| **Журнал и аналитика** | http://192.168.1.51:8080/ui | вводится на странице | статистика: карточки, по дням, по пользователям, по тикетам, журнал |
| **Swagger UI** | http://192.168.1.51:8080/docs | для запросов нужен (кнопка Authorize) | интерактивная документация API |

| **OpenAPI JSON** | http://192.168.1.51:8080/openapi.json | не нужен | схема API для генераторов клиентов |
| **Health** | http://192.168.1.51:8080/health | не нужен | статус сервиса и его параметры |

### Журнал и аналитика (`/ui`)

1. Вставьте токен в поле «Токен» и нажмите **Сохранить**. Токен запомнится в браузере.
2. Выберите период (7 или 30 дней), пользователя и/или тикет в выпадающих списках.
3. Смотрите карточки, график по дням, таблицы **«По пользователям»** и **«По тикетам»**, частые диагностики и последние проверки.
4. Если «неверный токен» — проверьте значение в `DEPLOY.local.md`.

Журнал хранит 30 дней. В нём нет текста кода: только пользователь, тикет, IP клиента, имя файла, размер, статус, счётчики и время проверки.

### Swagger (`/docs`)

1. Нажмите **Authorize**, в поле **Value** вставьте только токен (без слова `Bearer`), затем **Authorize** и **Close**.
2. Откройте эндпоинт, нажмите **Try it out**, заполните поля и **Execute**.

## Полный список адресов сервиса `bsl-api`

Таблица собрана из схемы `GET /openapi.json` и из маршрутов сервиса. Все адреса на порту 8080.

### Эндпоинты API

| Метод | Путь | Авторизация | Параметры / тело | Ответы | Что возвращает |
|---|---|---|---|---|---|
| GET | `/health` | нет | — | `200` | статус, `retention_days`, `timeout_sec`, `max_bytes`, `user_max`, `ticket_max`, `jira_base_url` |
| POST | `/check` | Bearer | JSON: `text` (обязательно), `user` (обязательно, до 150), `filename` (по умолчанию `Module.bsl`), `ticket` (необязательно, до 50) | `200`, `422` | результат проверки текста |
| POST | `/check/file` | Bearer | multipart: `file` (обязательно), `user` (обязательно, до 150), `ticket` (необязательно, до 50) | `200`, `422` | результат проверки файла |
| GET | `/api/stats` | Bearer | `days` (по умолчанию `30`), `user`, `ticket` (фильтры) | `200`, `422` | сводка: проверки, доля валидных, ошибки, по дням, `by_user`, `by_ticket`, частые коды, `values` |
| GET | `/api/journal` | Bearer | `limit` (по умолчанию `100`, максимум `500`), `offset`, `user`, `ticket` (фильтры) | `200`, `422` | записи журнала, новые сверху |

Коды ответов:
- `200` — успех.
- `401` — нет заголовка `Authorization: Bearer <токен>` или токен неверный.
- `400` — имя файла не `*.bsl`/`*.os`, или пустой вход.
- `413` — вход больше `BSL_MAX_BYTES` (по умолчанию 2 МБ).
- `422` — не передано обязательное поле (`user`), превышена длина `user` (150) или `ticket` (50), управляющие символы, неверный формат параметра.
- `504` — проверка не уложилась в `BSL_TIMEOUT_SEC` (по умолчанию 120 с).
- `500` — ошибка самого BSL-движка.

### Страницы и служебные адреса

| Адрес | Метод | Авторизация | Что показывает / делает | Кто использует |
|---|---|---|---|---|
| `/ui` | GET | нет (токен вводится на странице) | журнал и аналитика | человек в браузере |
| `/docs` | GET | нет | Swagger UI | человек в браузере |
| `/redoc` | GET | нет | ReDoc | человек в браузере |
| `/openapi.json` | GET | нет | схема API | генераторы клиентов, Swagger/ReDoc |

### Какие адреса вызывает страница `/ui`

Страница — один HTML-файл. Данные она получает запросами из браузера с токеном:
- `GET /health` — адрес Jira для ссылок (`jira_base_url`);
- `GET /api/stats?days=…&user=…&ticket=…` — карточки, график, разбивки, списки фильтров;
- `GET /api/journal?limit=200&user=…&ticket=…` — таблица последних проверок.

Токен хранится в `localStorage` браузера под ключом `bsl_token`.

### Кто ещё вызывает сервис

- **MCP-инструмент `check_bsl`** (`bsl-mcp/server.mjs`, OpenCode) — вызывает `POST /check` и `POST /check/file`. Имя пользователя подставляется автоматически (`USERNAME` Windows), `ticket` передаётся из аргументов инструмента. Адрес — переменная `BSL_SERVICE_URL`.
- **Скрипты и PowerShell** — те же эндпоинты, примеры в `bsl-api/README.md`.

## Что не проверено

Адреса из конфигурации, которые в этом проекте не проверялись (в таблицы не включены):
- `http://127.0.0.1:8011/mcp` (`code-index`) — на VM не отвечает;
- `http://localhost:6003/mcp` (`mcp-1c`) — отдельный сервис;
- `http://kali:3001/v1` (FreeLLMAPI) — есть контейнер `freellmapi`, страница не проверена.
